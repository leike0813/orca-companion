# 长 transcript 成本探针

这是讨论票「裁决长 transcript 的分页、虚拟化与懒加载机制」的隔离资产，使用假消息和临时 SQLite 数据库，不是产品实现。结果记录于 `results.json`。

```sh
node artifacts/transcript-performance-probe/probe.mjs /tmp/transcript-probe-results.json
```

需要当前项目已安装的依赖；复用现有换行函数和已安装的传递依赖 Marked，不安装新依赖。数据库位于系统临时目录，文件名为 `PROTOTYPE-fixture.sqlite`。

## 本机结果

2026-10-02，Node v24.12.0，Marked 17.0.1，SQLite WAL / synchronous FULL。每项先预热一次，再测五次；下表为中位数，不是 p95。历史假消息含中文和 ASCII；终端宽度为 120、80、50，视窗为 20 行。

| 消息数 | 历史 JSON 大小 | 整体读取后取尾部 | 索引读取尾部 100 条 | 整体追加 | 单条事务追加 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1,000 | 0.79 MB | 6.50 ms | 0.53 ms | 45.17 ms | 13.85 ms |
| 10,000 | 7.91 MB | 75.32 ms | 0.65 ms | 322.44 ms | 23.93 ms |
| 100,000 | 79.37 MB | 688.31 ms | 0.47 ms | 2,854.37 ms | 12.76 ms |

索引读取最早 100 条为 0.47–0.64 ms，读取 500 条上下文为 2.29–3.40 ms。100 条正文约 74 KiB，因此条数限制必须另配字节限制。历史视窗局部布局只访问 2–3 条假消息；与原始尾部 200 条布局的可见文本逐行相等。

| 单条代码正文 | 全量换行，三个宽度 | 16 KiB 范围换行，三个宽度 | 完整 Marked lexer |
| --- | ---: | ---: | ---: |
| 1 MiB | 37.29–51.22 ms | 0.45–0.57 ms | 2.46 ms |
| 5 MiB | 274.10–295.54 ms | 0.45–0.55 ms | 11.18 ms |

按 UTF-8 安全边界分块后重组与原文完全相等，范围读取约 0.01–0.02 ms。最长范围换行样本达到 26.71 ms，说明中位数不足以证明延迟上界。

## 结论和限制

原始历史规模进入普通尾部读取、追加和全量换行的成本；按身份索引读取和内容范围布局把成本约束到所需记录或内容。这个结果支持调整权威读取与增量写入，不能只在 TUI 对已读全量数据裁剪。

这里的规范化表只有最小假消息，不覆盖产品 Model Step / Wake Batch 的原子提交、恢复和 schema 校验；500 条读取也不是完整模型输入组装。局部布局仅比较源文本，不是跨段 Markdown 渲染器。长内容场景为多行 fenced code，尚未验证单行巨段、引用定义、表格、组合 emoji、完整搜索、持续流式输出或真实 PTY。

进程峰值 RSS 同时包含两种存储方案的假数据、完整历史数组和解析结果，不能用于选择产品缓存上限，也不能用来比较两种方案的内存。五次预热测量不能确定冷读、p95 或真实用户输入延迟。正式实现需补齐这些验收，不能把本资产当作产品性能通过证明。

本地 `@langchain/core/dist/language_models/chat_models.js` 的 `_streamIterator` 在 yield 后继续通过 `generationChunk.concat(chunk)` 聚合完整响应。展示层临时分块不等于 Provider / SDK 响应内存已受限；正式验收应分别报告展示缓存、有效模型上下文、当前响应聚合和进程 RSS。

脚本保留最小可运行断言：分页范围正确、追加不移动旧页边界、局部视窗文本等价、UTF-8 分块完整重组。它们验证探针本身的比较条件，不替代产品行为测试。
